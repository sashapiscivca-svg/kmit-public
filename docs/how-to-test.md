# Як перевірити застосунок

Стан на 2026-10-15. Усе нижче перевірено автоматично й у браузері на комп'ютері, а APK автор вручну перевірив на Android-телефоні. **Систематичного тестування на різних пристроях ще не було**, тому перевірка на ваших телефонах дуже допоможе.

## 1. У браузері на ноутбуці (найпростіше)

```bash
cargo fetch              # один раз: скрипти запускають Cargo з --offline
./scripts/dev.sh          # збере й запустить локальний сервер, дані: ~/.local/share/kmit-dev
```

Відкрий http://127.0.0.1:8765/ . Сервер слухає лише цей комп'ютер і зупиняється за Ctrl+C. Для вузького екрана телефону натисни F12 і ввімкни режим пристрою.

Що спробувати:
1. «Новий профіль»: ім'я, картинка, PIN (від 4 символів). Запиши код відновлення (показується один раз).
2. «Почати заняття». Спробуй хибну відповідь, потім «Підказка»: перша підказка не з'являється одразу (затримка), підказки не доходять до відповіді, схожа задача з розв'язанням показується лише для іншої задачі.
3. «Покажу дорослому»: задача відкладається, стікера немає.
4. Після заняття: «Альбом стікерів», «Аркуш для вчителя» (перегляд, PDF, друк).
5. «Для дорослого»: PIN дорослого, тихі години, відкладені задачі, новий код відновлення, експорт, видалення профілю.
6. «Вийти» і повторний вхід; хибний PIN.

## 2. Автоматичні перевірки

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace                        # 494 функції #[test] (480 у звичайному запуску; решта потребує feature reviewer або позначена #[ignore])
scripts/check_ui.sh                           # синтаксис JS і сумісність зі старими WebView
CHROME=/шлях/до/chrome THEME=light ./scripts/e2e.sh   # наскрізний тест інтерфейсу в headless Chromium (також THEME=dark)
CHROME=/шлях/до/chrome ./scripts/e2e-reviewer.sh      # наскрізний тест застосунку методиста
```

## 3. Android

Збірка: `app/src-tauri` (Tauri 2). Інструменти, середовище, підпис і перевірку дозволів описано в [BUILDING.md](../BUILDING.md). Усе, що належить пристрою (WebView на старих телефонах, TalkBack, швидкість Argon2, збереження PDF, озвучення, Keystore), **не перевірено**.

Вимоги: для e2e потрібен Node ≥ 22. Цільовий мінімальний WebView для інтерфейсу: Chromium ≈ 80 (на пристроях не перевірено; `scripts/check_ui.sh` забороняє новіші можливості мови, `replaceChildren` доповнено поліфілом).

## Окремі набори тестів
- Ядро: `cargo test -p app-core --test teacher_tests --test teacher_work_tests --test teacher_lesson_tests --test compliance_tests`; сховище: `cargo test -p storage --test kind_tests`; PDF: `cargo test -p report --test work_tests`; застосунок методиста: `cargo test -p app-core --features reviewer,test-support --test reviewer_tests` і `CHROME=… scripts/e2e-reviewer.sh`.
- e2e (`scripts/e2e.sh`): наприкінці сценарій «профіль вчителя» (вибір ролі, кабінет, роботи, нотатки, тематичний план, дані й налаштування).
- Вручну в браузері: `scripts/dev.sh`, на екрані профілів «Новий профіль» → «Я вчитель або вчителька»; PDF «Завдання/Ключ/Бланк відповідей» відкрити й подивитися (`pdftoppm -r 50 -png файл.pdf out`).
- Вміст: `cargo test -p subjects` (структура, довжини, читабельність, гендерні форми); `cargo run -p content-tools -- validate crates/subjects/packs`. Для чернеток нових одиниць вмісту (тека з файлами `skill-*.json`): `python3 scripts/pack_lint.py <тека> [--lang-mixed-ok]`, сліпа перевірка ключів `scripts/blind_quiz.py export|compare`, злиття `scripts/pack_merge.py`.
