# Процес огляду вмісту методистами

Мета: методист перевіряє й виправляє вміст, не чіпаючи код. Розробник застосовує виправлення одним кроком і випускає підписаний пакет.

## Для методиста

1. Розробник дає теку `review/` з файлами `<предмет>.html` (для читання) і `<предмет>.csv` (для заповнення в Excel/LibreOffice/Google Таблицях).
2. Кожен рядок CSV це один текст: умова, варіант відповіді, пояснення, підказка, абзац уроку. Стовпці:
   `pack, skill, kind, index, field, text, status, correction, comment`.
3. Заповни лише три останні стовпці:
   - `status`: `ok` (усе добре), `fix` (є виправлення), `remove` (завдання прибрати);
   - `correction`: новий текст (для `fix`);
   - `comment`: чому, посилання на підручник або програму.
4. Стовпець `text` не змінюй: за ним розробник перевіряє, що виправлення стосується саме цього тексту.
5. Що варто перевірити: фактична правильність; відповідність програмі й підручнику; мова (без форм, що залежать від статі дитини); чи підказки не називають відповідь; чи складність підходить для свого класу.
6. Збережи як CSV (UTF-8) і поверни розробнику.

Увесь вміст створено за допомогою ШІ-агентів і перевірено лише автоматично (лінт і сліпа перевірка ключів), тож остаточне рішення щодо фактів і методики за методистом.

## Для розробника

Інструмент: `cargo run -p content-tools -- <команда>`.

```
validate <тека пакетів>                           перевірка формату
review   <тека пакетів> <тека виводу>             CSV і HTML для методиста
apply    <тека пакетів> <review.csv>              застосувати fix/remove, підняти версії
keygen   <файл приватного ключа>                  створити ключ (друкує відкритий)
sign     <файл приватного ключа> <пакет.json>     створити <пакет>.sig
verify   <пакет.json> <пакет.sig> <відкритий ключ hex>
```

Порядок:
1. `review crates/subjects/packs review/`: віддати методисту.
2. Отримати `review.csv` → `apply crates/subjects/packs review.csv`. Рядки, де `text` уже не збігається з пакетом (звіт застарів), пропускаються й друкуються. Версія пакета зростає автоматично.
3. `validate crates/subjects/packs` і `cargo test -p subjects` (лінт, довжини, читабельність, гендерні форми).
4. Підписати: `sign <ключ> crates/subjects/packs/<id>.json`.
5. Передати дітям: або новий випуск застосунку (пакет вбудований), або пара файлів `<id>.json` + `<id>.sig` для «Час і захист» → «Оновлення вмісту». Застосунок приймає лише пакет із чинним підписом і вищою версією.

## Ключ підпису
Зараз у застосунку вбудований тестовий відкритий ключ розробника (приватний лежить поза репозиторієм). Справжній ключ треба згенерувати перед випуском (`keygen`), приватну частину зберігати офлайн, відкриту вписати в `PUBLISHER_PUBLIC_KEY` (`crates/subjects/src/pack.rs`).

## Відомі обмеження
- Один рядок CSV править один текст; додавання нових завдань робиться редагуванням JSON (формат у [content-packs.md](content-packs.md)).
- Малюнки в уроках (`figure`) редагуються лише в JSON.
- Порядок варіантів у квізах уроків застосунок перемішує сам; в авторському тексті правильний варіант можна ставити першим (`correct: 0`), але пояснення не повинні посилатись на «перший/другий варіант».
