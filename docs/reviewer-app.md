# Застосунок методиста (закритий, поза Google Play)

Окремий APK `Kmit Методист` (`ua.kmit.reviewer`), без ключів, розсилається поштою. Змінює лише збірка; дитячий і вчительський застосунки не містять входу методиста.

## Збірка й розсилка
`scripts/android-reviewer-apk.sh` → `~/kmit-release/kmit-reviewer-arm64-test.apk` (підпис тестовим ключем; для розсилки потрібен один постійний ключ: `KMIT_KEYSTORE`, `KMIT_KEY_ALIAS`, `KMIT_STORE_PASS`, `KMIT_KEY_PASS`, бо оновлення потребують однакового підпису). Скрипт друкує пакет і дозволи: INTERNET немає.

Збірка має Cargo-feature `reviewer` (`app-core`): лише команди `rv_*` та новий код відновлення; дитячі профілі, вчительські команди й імпорт відмовляють, профіль один. Власний інтерфейс у `app/reviewer` (збирається `scripts/build-reviewer-ui.sh`), власний значок (`scripts/make_icons.py reviewer`).

## Що робить методист
1. Встановлює APK, створює профіль (ім'я для назви файлу й PIN; код відновлення зберігає).
2. Бачить прогрес за всіма темами, класи й предмети; «Продовжити» відкриває першу тему й перше завдання без позначки. Тема має розділи «Урок», «Завдання» (по одному), «Підсумок».
3. До кожного тексту: «Усе гаразд» (одним дотиком, далі автоматично наступне завдання), «Виправити» (новий текст і коментар; незбережена чернетка не губиться при переході між завданнями), «Прибрати завдання» (з підтвердженням; в темі має лишитися хоча б одне завдання). Решту без позначки можна позначити разом.
4. «Надіслати файл» зберігає `vychytka-<ім'я>-<дата>.csv` (для однієї теми: `vychytka-<ім'я>-<тема>-<дата>.csv`); методист пересилає його розробникові. Застосунок нічого не надсилає сам.

## Що робить розробник
```
cargo run -p content-tools -- apply crates/subjects/packs vychytka-….csv   # застосовує виправлення й прибирання, підвищує версії, друкує пропущені рядки
git diff crates/subjects/packs                                            # перегляд змін перед комітом
cargo run -p content-tools -- approve crates/subjects/packs <id пакета> reviewed "<ініціали>" <дата>   # статус; піднімає версію ще раз
```
Версія пакета зростає при `apply` і ще раз при `approve`: це нормально, оновлення просто замінить попереднє.

## Правила, які варто знати
- Позначка діє, лише поки текст у пакеті той самий. Після `apply` (прибрані завдання зсувають індекси) і нового APK старі позначки на змінених текстах стають **застарілими**: застосунок показує їх кількість, не враховує й не експортує. Нових позначок методист ставить лише на змінене.
- «Усе гаразд» у файлі це рядок зі статусом `ok` і порожнім текстом: `apply` його ігнорує, а розробнику він показує, що перевірено.
- Виправлення й «прибрати» одного завдання не затирають одне одного (різні ключі). `apply` застосовує `fix` (з перевіркою, що текст у пакеті досі той самий), потім `remove`.
- Ємність: до 30 000 позначок. Якщо місця бракує, застосунок пропонує надіслати файл і почати з наступних тем (масова позначка нічого не додає частково).
- CSV відкривається в електронній таблиці лише для перегляду: клітинки, що починаються з `=`, `+`, `-`, `@`, можуть бути сприйняті як формули. Застосовувати файл слід `content-tools apply`, а не зберігати з таблиці.

## Перевірка
`cargo test -p app-core --features reviewer,test-support --test reviewer_tests` (в тому числі повний круг: файл → `apply` → виправлені підказки й прибрані завдання), `CHROME=… scripts/e2e-reviewer.sh` (збирає інтерфейс методиста й проходить увесь шлях: вхід, позначки, чернетки, «Назад», блокування, відновлення, налаштування, видалення). Час відповіді в `--release`: перший огляд ≈ 0,2 с, позначка ≈ 10 мс (`… perf -- --ignored --nocapture`).
